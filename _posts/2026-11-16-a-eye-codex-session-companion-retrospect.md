AI 코딩 도구의 작업을 검토하려면 최종 답변만으로는 부족하다. 어떤 명령이 실행됐고, 어떤 파일이 바뀌었으며, 테스트가 통과했는지 이어서 봐야 한다. A_eye는 Codex 세션 기록을 단계별로 정리하고 진행 중인 작업을 보여주는 Windows 데스크톱 앱이다. Electron과 React로 화면을 구성하고, 정규화한 기록은 앱 소유의 SQLite 데이터베이스에 저장한다([A_eye의 프로젝트 설명](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/README.md)).

## 기록은 그대로 화면에 뿌리지 않는다

Codex의 실행 기록은 JSONL 형식이다. 한 줄에 이벤트 하나를 담지만, 사용자 메시지·명령·도구 결과가 같은 형태로 들어오지는 않는다. A_eye의 파서는 줄을 읽어 이벤트를 분류하고, 명령 실행·파일 변경·테스트 증거를 별도로 추출한다. 깨진 줄이나 지나치게 긴 줄도 오류 이벤트로 남긴다([세션 파서 구현](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/src/main/rolloutParser.ts)).

이후 단계 엔진은 이벤트를 계획·구현·검증 등의 묶음으로 만든다. 도중에 끝난 턴에는 중단 표시를 남긴다. 이렇게 하면 긴 로그를 시간순으로 훑지 않아도 작업 흐름과 멈춘 지점을 찾을 수 있다([단계 추론 구현](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/src/main/stageEngine.ts)). 다만 단계 이름은 원본 기록에 항상 쓰여 있는 사실이 아니라 이벤트를 바탕으로 한 **분류 결과**다. 화면에서도 원본 증거로 돌아갈 길이 필요하다.

## 시작 속도와 기록 충실도를 나눈다

과거 세션을 시작할 때 모두 깊게 분석하면 앱의 첫 화면이 늦어진다. A_eye는 5MB를 넘는 기록을 시작 시점에 전체 파싱하지 않고, 세션 메타데이터부터 등록한다([수집기 구현](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/src/main/ingestor.ts)). 여기서 5MB는 분석 정확도의 기준이 아니라 초기 처리량을 제한하는 구현상의 경계다.

| 데이터 | 처음 열 때 | 상세 검토할 때 |
|---|---|---|
| 일반 크기의 과거 세션 | 이벤트를 읽어 단계와 증거를 만든다 | 단계별 명령·파일·테스트를 확인한다 |
| 5MB 초과 과거 세션 | 우선 세션 메타데이터를 등록한다 | 필요한 기록을 별도로 읽어야 한다 |
| 진행 중인 작업 | 실시간 이벤트를 받는다 | 승인 요청과 결과를 작업 맥락에서 확인한다 |

*작성자 정리. 표는 [세션 수집기](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/src/main/ingestor.ts)와 [실시간 작업 관리자](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/src/main/liveRunManager.ts)의 역할을 요약했다.*

표에서 핵심은 오래된 기록과 현재 진행 중인 작업의 처리 경로가 다르다는 점이다. 과거 기록은 재구성해 읽고, 현재 작업은 새 이벤트가 들어올 때 상태를 갱신한다. 둘을 같은 목록에 놓더라도 데이터가 만들어지는 방식은 구분해야 한다.

## 화면의 권한은 연결 통로에서 제한한다

세션 기록을 읽으려면 로컬 파일 접근이 필요하다. 그러나 화면 코드에 파일 시스템과 프로세스 권한을 직접 주면 표시 기능이 실행 권한까지 갖게 된다. A_eye는 Electron의 preload와 IPC를 통해 화면이 호출할 수 있는 기능을 정한다. 세션 조회, 프로젝트 선택, 진행 작업 조회, 승인 결정 등이 명시된 통로를 지난다([preload의 IPC 연결](https://github.com/dorec9/A_eye/blob/50e80e45c6c6ec608e4ae6d9d1df6557bb1ec0c0/src/main/preload.ts)).

이 프로젝트의 설계 판단은 두 경계로 정리된다. 첫째, 원본 이벤트와 해석된 단계를 분리해 검토 가능성을 남긴다. 둘째, 로컬 권한을 가진 프로세스와 화면의 호출 범위를 분리한다. 작업 관제 화면은 보기 쉬워야 하지만, 그 편의가 기록의 근거나 실행 권한을 흐려서는 안 된다.
