# 금지 표현

## 과장 수식어 (사용 불가)
혁신적인, 획기적인, 놀라운, 강력한, 완벽한, 최적의, 궁극적인

## AI 특유 표현 (사용 불가)
살펴보겠습니다, ~해 보도록 하겠습니다, 마무리하며,
지금까지 ~에 대해 알아보았습니다, ~의 세계로 떠나볼까요

## 빈 수식어 (구체적 수치로 대체)
- 다양한 → 구체적 개수 (예: "3가지 방법")
- 효과적인 → 어떤 지표가 얼마나 개선되는지
- 체계적인 → 실제 구조/단계를 기술
- 빠르게 → 소요 시간 명시

## 대체 원칙
수식어를 빼도 문장이 성립하면 빼라.

## 공개하지 않는 정보 (모든 포스트 공통)
글은 공개되고 검색엔진에 색인된다. 아래는 본문에 쓰지 않는다.

- **운영자 본인이 굴리는 사이트·서버 주소** — 개인 사이트/서비스의 도메인·URL,
  서버 IP, 내부 호스트명, 포트, 배포 대상 주소(nginx server_name 등)
  - 예외: 이 블로그(dorec9.github.io)와 GitHub 프로필 링크. 그건 공개된 신원이다
- API 키·토큰·비밀번호·인증서, .env의 실제 값 (예시 형식만 쓴다)
- 비공개 API 엔드포인트 전체 경로, DB 실제 접속 정보
- 본인 외 팀원의 실명·이메일·계정
- 클라이언트·회사명이 드러나는 식별 정보

원칙: 아키텍처와 설계 판단은 쓰고, 실제로 접속할 수 있는 주소·자격증명은 뺀다.
"리버스 프록시로 3개 서비스를 라우팅했다"는 쓰되 그 도메인은 쓰지 않는다.
