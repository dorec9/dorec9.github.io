# PC 없이 발행하는 설정

## 현재 운영: 구독 기반 클라우드 예약

`블로그 평일 클라우드 발행` 예약 작업을 평일 09:17 KST로 등록했다. 첫 예약은 2026-11-23 09:17 KST다. 예약 정보에서 실행 환경이 사용자 PC가 아닌 **Default Cloud**로 연결되어 있는지 확인한다. 일정 등록과 글의 실제 발행 성공은 구분하며, 각 실행의 결과를 확인한다.

이 경로는 현재 에이전트의 구독 기반 실행과 연결된 GitHub 도구를 사용한다. 별도 `OPENAI_API_KEY`나 사용자 PC의 Codex 인증 파일을 요구하지 않는다. 구독의 모델 사용량 한도는 적용된다. 웹 검색, GitHub 연결, 클라우드 환경 또는 권한이 막히면 실행 결과에 오류를 남긴다.

### 실행 절차

1. 클라우드에서 최신 `dorec9/dorec9.github.io`의 `main`을 받는다. 이전 실행의 미커밋 변경을 덮어쓰지 않고 필요하면 새 임시 디렉터리에 clone한다.
2. `AGENTS.md`와 품질 규칙, 발행 이력을 읽고 실제 KST 날짜에 맞는 글 한 편을 작성한다. 과거 복구 대기열이 완료됐다는 이유로 정기 발행을 중단하지 않는다.
3. 새 글에 `python scripts/validate_post.py <포스트 경로>`를 실행하고 `bash scripts/build_site.sh`, `git diff --check`를 통과시킨다. 빌드 도구가 없거나 의존성 설치가 실패해도 검증 성공으로 취급하지 않는다.
4. 업로드 직전 원격 날짜 중복과 `main` SHA를 다시 확인한다. GitHub 연결의 tree·commit·조건부 ref 갱신으로 포스트와 이력을 한 커밋에 반영한다. 원격 변경을 덮어쓰거나 force push하지 않는다.
5. 원격 커밋, 해당 커밋의 GitHub Pages 배포 성공, 실제 게시 URL과 제목까지 확인하고 결과를 보고한다. 이미 커밋한 뒤 게시 확인만 실패하면 포스트를 다시 만들지 않는다.

월요일은 회고할 공개 가능한 저장소 변경이 없으면 사유를 기록하고 건너뛴다. 화~금은 해당 카테고리의 글을 발행한다. 같은 KST 날짜 글이 이미 있으면 게시 상태만 확인한다. 주말 수동 시험은 최신 글 검증·빌드·게시 URL 확인만 수행한다.

### 빌드 환경

`scripts/build_site.sh`는 Ruby 3.1과 Bundler가 있으면 로컬로 빌드하고, 없으면 Docker의 Ruby 3.1 이미지로 빌드한다. 의존성은 무시되는 `vendor/` 등에 설치하고 결과 `_site/`와 함께 커밋하지 않는다. 클라우드에는 Python 3, Git, 네트워크 접근 및 Ruby/Bundler 또는 Docker가 필요하다.

### 기존 일정과 중복 방지

과거 로컬 `dorec9 평일 블로그 정기 발행` 예약은 별도 설정이다. 새 클라우드 예약을 등록했다고 자동으로 중지되는 것은 아니다. 기존 예약이 켜져 있으면 해당 앱에서 중지해 실행 주체를 하나로 유지한다. 현재 채팅의 예약 조회에서 로컬 예약의 상태를 확인하지 못했으므로 중지 완료로 간주하지 않는다.

두 작업이 겹칠 때도 업로드 직전 날짜 재확인과 SHA 조건부 반영으로 기존 글을 보호한다. 월요일 변경 없음·날짜 중복·검증 오류를 구분하고, 예약 상태와 실제 결과를 함께 확인한다.

## 대안: 별도 API 기반 GitHub Actions

`.github/workflows/auto-publish-cloud.yml`은 위 구독 예약과 다른 실행 경로다. `AUTO_PUBLISH_CLOUD_ENABLED`가 정확히 `true`일 때만 실행하며, `OPENAI_API_KEY`를 사용한다. 현재 구독 기반 운영에서는 이 변수를 켜지 않는다.

API 방식으로 별도 전환하기로 한 경우에만 다음 절차를 따른다.

1. OpenAI API 결제와 사용 한도를 확인하고 API 키를 GitHub Actions의 Repository secret `OPENAI_API_KEY`로 저장한다. 키나 구독 인증 파일을 저장소·이슈·채팅에 입력하지 않는다.
2. 저장소 변수 `AUTO_PUBLISH_CLOUD_ENABLED=true`를 설정한다.
3. 미발행 평일에 수동 시험하여 새 글 한 편, 원격 커밋, Pages 빌드, 실제 URL을 확인한다.
4. 전환이 확인되면 다른 구독·로컬 예약을 중지한다.

이 Actions는 `GITHUB_TOKEN` push 뒤 Pages 빌드를 별도로 요청한다. 실패하면 실행 로그 링크가 담긴 이슈를 만든다. GitHub 일정은 부하에 따라 지연·누락될 수 있고, 공개 저장소가 60일 동안 활동이 없으면 예약 워크플로가 비활성화될 수 있다.
